## Test layers

Use the smallest layer that proves the behavior, then expand by risk:

1. deterministic unit tests with fake clocks, fake processes, and injected I/O.
2. Windows process-only tests for sharing, identity, Job Objects, pipes, and
   cleanup.
3. repository integration tests for stdio, package boundaries, schemas, and
   receipts without COMSOL.
4. opt-in licensed COMSOL acceptance for release-specific clientapi or physical
   behavior.

Tests should assert observable behavior and independent evidence, not private
implementation metadata. Include accepted boundary equality, one-step-beyond
rejection, rollback, cleanup, replay, and corruption cases.

Bind outcome assertions to durable state as well as the returned summary. A
resource refusal before work must expose the gate decision and persist no false
row. A replay/skip result must still prove that the prior complete rows and
collector summaries exist on disk. Do not use temporary lock-file presence or
absence as an oracle unless lock visibility is itself a public contract.

Use fresh fake models, stores, processes, and clients for resume or recovery
phases. Reusing one mutable fake can let state from the first phase make a
broken recovery path pass. For generated artifacts, compare checked-in bytes to
independently regenerated bytes rather than duplicating a hand-maintained
expected payload.

## Native regression evidence

Use a controlled native fixture when the defect concerns model loading, API
readback, or audit transport. A private research model is unnecessary unless
the claim depends on its physics. Freeze the fixture conventions before the gate.
Preserve the gate's existing thresholds and caller-approved resource limits.

For loaded-source attestation, hash the exact frozen file before and after
loading. Pass that captured identity to the audit. A matching file hash alone
does not establish which bytes the live model loaded.

Bind both execution and independent acceptance to the current source identity.
Recheck tracked files, settings, model bytes, declared artifacts, and fresh
ownership after execution. Historical receipts retain their original source scope.
Separate successful execution from independent acceptance and final release approval.

Recompute derivative errors, signs, chosen steps, cosine, and directional products
from raw evidence. Check native receipt bindings against the referenced files.
Preserve the producer's declared operation order near floating-point cancellation.
Use resealed contradictory receipts to test semantic checks beyond hash validation.

Before a licensed optimizer test, inspect the exact derivative support supplied to the production adapter.
An empty constraint list cannot establish constrained convergence.
Use an active constraint that changes the optimum relative to an unconstrained control.
Check native constraint activation, expressions, bounds, and the declared convergence criteria.
Check feasibility and the objective with a fresh independent forward solve.
An iteration limit alone does not establish convergence.

COMSOL 6.4 can read back explicit `constraintActive=["on"]` and then fail Optimization equation compilation.
A controlled comparison compiles when only this property returns to its native empty default.
Preserve constraint expressions and bounds during this comparison.
Record the empty default exactly. Do not report an invented `on` readback.
Keep property acceptance, equation compilation and constrained convergence as separate gates.
Verify actual constraint enforcement against an active-bound oracle and a fresh forward solve.
This observation does not establish the behavior of every COMSOL version or feature.

After a native optimizer timeout, test a known analytic baseline with one bounded sensitivity study.
Compare the raw native derivative with the independently derived value in matching units.
A correct baseline derivative does not prove optimizer convergence or identify the timeout cause.
Use measured point cost as an estimate, not a guaranteed campaign duration.
Keep later execution within the caller's declared resource limits.

Declare any test-only input factory or node resolver replacement in native evidence.
Keep production typed getters, conversion, constraint configuration, and solver operations unchanged.
Capture native configuration and forward control values through read-only observers.
Separate an accepted getter result from public adapter path support and scientific validation.

Licensed integration suites can contain both source probes and installed-server probes.
An installed-server probe can clear PYTHONPATH and launch outside the checkout.
Use an isolated interpreter with the accepted wheel and declared test dependencies.
Attribute a missing installed package before diagnosing a closed MCP connection as a transport defect.

Forward the declared core count to every native constructor and lifecycle restart.
An environment variable alone does not prove that each child uses its value.
Verify actual lifecycle arguments and retain effective resource settings in the receipt.
For standalone clients, clear owned models and end the contained process.
Call disconnect only when the client has an attached server port.
Cleanup exceptions must still fail the gate.

Prevalidate a cancellation fixture against the unchanged gate bounds before cancellation acceptance.
A lossless scattering fixture can have a small negative numerical absorption residual.
That residual can fail a strict nonnegative bound before the job reaches the cancellation phase.
Use a separately declared fixture that satisfies the bound. Preserve the original failed evidence.
Keep fixture preparation, cancellation execution and physical validation as separate claims.

## Solver-free enforcement

Unit, lint, compile, documentation, schema, wheel, sdist, and default CI must not
construct `mph.Client`, start Java, or launch COMSOL. Use explicit observers or
receipts to prove `solver_started=false` rather than relying on convention.

Keep native-backed imports that can stall the event loop either preloaded before
dispatch or isolated in bounded subprocesses. A fresh-stdio test matrix should
cover representative cold paths.

## Local and hosted execution policy

Follow the current repository `AGENTS.md` commands exactly. Keep the measured
local worker count bounded and retain any declared serial tail for startup or
process-inventory tests. Do not replace it with `-n auto` without a new timing,
isolation, cleanup, and coverage benchmark.

On Windows, account for the path depth added by the gate run ID, xdist worker,
pytest test name, durable job ID, and artifact identity. Put complete quality
and release gate artifact roots and pytest basetemps directly under the
approved ASCII test root with a leaf that satisfies the repository-declared
path budget. Do not use descriptive nested gate roots. A Win32 temporary-file
`FileNotFoundError` under a deep generated path is first a gate-invocation path
failure. Rerun from a short root only after confirming the failed tests pass
there.

GitHub-hosted Windows execution may require serial pytest even when local xdist
is stable. Different hosted jobs have stalled during worker dispatch or
shutdown. Do not restore hosted xdist until an upstream fix or a new repeated
stability benchmark justifies it.

For real Tk layout tests on GitHub-hosted Windows, do not assume a successful
`setup-python` step proves that Tcl/Tk payload files are usable. Floating minor
versions can select a damaged or incomplete hosted toolcache. Keep the action
on its reviewed current release, pin the GUI job to an exact official Python
patch artifact known to contain Tcl/Tk, and run a minimal `tk.Tk()` create,
withdraw, idle-update, and destroy preflight before installing the project. If
the exact official artifact repeatedly fails that preflight, keep real-window
layout and DPI acceptance in the local Windows gate. Retain non-window GUI
contracts in CI, and never silently skip the missing runtime as a green layout
result.

When backend, dependency, package, and GUI gates share the same push, pull
request, permissions, and cancellation policy, keep them as independent jobs in
one solver-free workflow. This preserves separate required-status points and
failure localization while producing one workflow run identity per source SHA.
Use a separate workflow only when triggers, permissions, secrets, lifecycle, or
licensed side effects genuinely differ. Exact-SHA acceptance must inspect every
required job in the unified run.

Never start a full local suite or gate while a heavy COMSOL solve is active. A
heavy solve may exhaust the host alone. Overlap only increases the risk.

## Deterministic time and warnings

Keep ordinary unit tests independent of the wall clock. Pin the review date or
derive it from a checked-in fixture. Enforce “current as of today” in a dedicated
CI or release command gate whose purpose is freshness.

Treat `ResourceWarning` as lifecycle evidence. Close files, SQLite connections,
pipes, subprocess streams, executors, and temporary resources deterministically.
Run focused suites with warnings promoted to errors when repairing cleanup.

For Windows PowerShell child acceptance, give each case an isolated output
directory and enforce an independent wall-clock timeout. When stdout and stderr
are redirected, drain both asynchronously before waiting so the timeout cannot
hide a pipe deadlock. Terminate only the exact child identity on expiry.

Serialize floating-point evidence with invariant round-trip formatting and
parse it with the same culture in tests. Prefix regexes and locale-default
string conversion are not exact scientific-value oracles.

For timing tests, use fake clocks when possible and independent absolute
ceilings when real scheduling is unavoidable. Do not tighten a relative timing
assertion until it survives process-enumeration and hosted-runner load.

Acceptance scripts must take their receipt, lock, runtime, and pytest roots
from an explicit ASCII test-root contract. Never let an acceptance default write
into production runtime state.

When Git reports modified files but both index and worktree diffs are empty,
prove blob equality before treating the entries as stat/EOL noise. Refresh by
staging tracked content only when the resulting cached diff is still empty.
Never discard or reset a user's real change to satisfy a clean release gate.

## Failure diagnosis

Bind diagnosis to the exact commit SHA, workflow run, job, and step. Extract the
first actual traceback or failed assertion instead of inferring from elapsed
time or a progress percentage.

Classify separately:

- deterministic assertion/schema/allowlist mismatch.
- timeout with diagnostic stack.
- worker or executor shutdown stall.
- process/pipe/resource leak.
- host resource exhaustion.
- dependency-lane incompatibility.
- packaging or installed-source mismatch.

One deterministic failure repeated in several jobs is one root cause, not
several independent CI defects. Update generated fingerprints or allowlists only
after proving the matched semantic surface is intentionally unchanged.

## Quality gate and release gate

The quality gate runs formatting/lint, the solver-free test split, coverage,
license, budget, and receipt checks in the working tree. It is a development
gate and may permit an explicitly identified dirty tree.

The release gate proves a clean, locked, reproducible release candidate. It
should verify dependency locks, wheel/sdist contents, clean non-editable install,
installed schemas/profiles/build identity, stdio discovery, and absence of a
COMSOL client. A quality pass does not substitute for the release gate.

## Long-run waiting and stability

For a test or gate expected to exceed three minutes, wait once for the current
ETA plus a small margin instead of frequent polling. If it remains active,
derive a new ETA from observed progress and repeat the bounded wait.

Do not call an intermittent stall fixed after one pass. Establish a fresh
post-fix baseline and require the repository-declared consecutive exact-SHA CI
window. Distinguish a fast deterministic failure from a no-progress stall when
counting stability.

## Optional stage launch coverage

Resolve the selected stage budget before reading optional stage fields.
A dictionary of evaluated values reads every field before key selection.
Disabled optimizer stages must not require their optional budgets.
Test the actual child-launch path with a short solver-free subprocess.
Check the selected timeout and persisted child receipt.
Cover disabled optional stages and explicitly enabled comparison stages.
Replacing the entire child runner cannot check launch preparation.

## Independent optimizer feasibility

A native optimizer can return a low objective while violating a configured active constraint.
A matching fresh forward objective does not establish constraint feasibility.
Evaluate every declared constraint in both the optimizer dataset and the fresh forward dataset.
Pass the declared unit and select the final solution explicitly.
Reject nonfinite, complex or nonscalar values before comparing the declared bounds.
Preserve caller tolerances when the contract declares them.
Keep raw values, units, bounds and dataset identities in the receipt.
Reject an infeasible result even when the native solver reports success.
Use an active-bound analytic oracle to distinguish constrained and unconstrained optima.
An empty activation readback and successful compilation do not prove constraint enforcement.
A gradient-method comparison can improve execution without fixing constraint enforcement.

## Constraint tolerance provenance

A strict zero-violation guard can reject results that satisfy a frozen caller tolerance.
Pass each declared constraint tolerance explicitly to both optimizer and fresh forward checks.
Bind each tolerance to its constraint identifier and expression unit.
Reject missing identifiers, unknown identifiers, negative values and nonfinite values.
Keep the default strict when the caller provides no tolerance.
An algebraically equivalent dimensionless constraint requires the corresponding tolerance transformation.
Record raw residuals and the applied tolerance before acceptance.
Preserve the original failed receipt when a guard prevents the fresh forward stage.
Do not infer convergence from a residual alone when the full frozen oracle remains incomplete.


## Native constraint scaling

A controlled COMSOL 6.4 GCMMA comparison confirms that constraint scaling can change practical enforcement.
The dimensional constraint misses its active bound despite a low objective.
An equivalent dimensionless residual passes the frozen numerical oracle with an explicit adjoint gradient.
A fresh forward solve confirms the final controls, objective and constraint residual.
This evidence applies to the controlled fixture and configuration.
It does not establish a universal solver default or physical correctness.
When testing this behavior, preserve the physical bound.
Transform its feasibility tolerance into the new expression unit.
Keep the objective, gradient method, mesh, move limit and budgets fixed during the comparison.
Confirm the active bound, stationarity and objective independently after optimization.
Keep numerical optimizer acceptance separate from passivity and other physical acceptance criteria.


## Child source identity

A parent process can import the candidate checkout while its detached worker imports an older installed package.
Changes to the parent's sys.path do not propagate to a new Python interpreter.
For source acceptance, bind the child working directory or PYTHONPATH explicitly.
For installed acceptance, use the accepted interpreter outside the checkout and clear source overrides.
Record the child module path and content identity before licensed work.
A parent commit check alone does not establish the worker source identity.
If the child identity differs, cancel the exact attempt and preserve its consumed resources.
Check cleanup before a corrected run.
